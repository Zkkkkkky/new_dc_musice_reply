# 三目童子五曲精修驱动转换

## 交付结果

用户提供的五个《三目童子》NSF 已转换为 ROM 精修曲使用的 `$F000/$F100/$F160` 公共驱动格式。成品位于：

`dist/music/三目童子（精修通用驱动）/`

版本化 NSF 与可编辑 FamiStudio 文本工程位于：

`assets/music/02 三目童子（精修通用驱动）/`

本次只交付五个同驱动 NSF，没有将它们绑定到 ROM 命令或场景。

## 源文件关系

五个原 NSF 每个都是 14,389 字节，加载/初始化/播放入口为 `$8000/$B7B0/$8000`。除文件偏移 `$3831`（CPU `$B7B1`）的曲号 `$05-$09` 外，其余 14,388 字节完全相同。

| 曲目 | 原曲号 | 原循环帧数 | 成品大小 |
| --- | ---: | ---: | ---: |
| Stage 5-2 | `$05` | 3264 | 12,416 |
| Stage 5-3 | `$06` | 2560 | 8,320 |
| Boss Fight | `$07` | 12544 | 16,512 |
| Introduction | `$08` | 2048 | 8,320 |
| Ending (Epilogue) | `$09` | 2880 | 8,320 |

## 转换方法

`tools/convert_mitsume_to_refined_driver.py` 执行以下流程：

1. 校验五个输入只在 `$B7B1` 曲号上不同。
2. 用 6502 执行器跟踪原驱动，以完整 RAM 状态或最终 APU 周期序列确定真实循环。
3. 用 FamiStudio 4.5.3 的 NSF 导入器将实际 APU 演奏轨迹重建为可编辑工程。
4. 以一帧为一个时间单位，精确裁切循环；只允许调整开头不可闻的静音帧，不改变可听内容或循环长度。
5. 导出标准 NSF，将首个 4 KiB 驱动页替换为当前 ROM 精修曲的锁定公共驱动。
6. 比较替换前后的逐帧目标周期、音量、占空比、三角波和噪声状态。

重建示例：

```powershell
python tools/convert_mitsume_to_refined_driver.py `
  --input-dir <五个原NSF所在目录> `
  --famistudio <FamiStudio.exe> `
  --pydeps <包含py65的目录>
```

## 验证结论

- 五个成品的驱动页 SHA-256 均为 `20C0C421ADCE739DB24D8C9D445FB1FC6052C59668B3405967156833F402D431`，与 ROM 精修曲公共驱动相同。
- 公共驱动重绑前后，所有验证帧的目标音高/音量状态差异为 0。
- 五首的方波开关、占空比、音量，三角波音高，噪声音量/周期均逐帧一致。
- `Introduction` 的两个方波各有 216 帧使用原机硬件扫频；转换工程将实际听到的扫频音高展开为公共驱动逐帧音高，非扫频帧的音高误差为 0。
