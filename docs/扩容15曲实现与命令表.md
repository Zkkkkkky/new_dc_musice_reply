# 扩容 15 曲实现与命令表

## 交付状态

`新DC上.nes` 与 `新DC下.nes` 已分别生成一份未绑定版：

- `dist/roms/新DC上_扩容15曲_未绑定.nes`
- `dist/roms/新DC下_扩容15曲_未绑定.nes`

另有两份从用户已修改扩容 ROM 原样保留旧区后修复的交付物：

- `dist/roms/新DC上_扩容15曲_音频时序修复.nes`
- `dist/roms/新DC下_扩容15曲_音频时序修复.nes`

“未绑定”表示 15 首曲目已经进入 ROM、可以用命令触发，但没有猜测角色、地图或剧情事件的最终分配。这样可避免在没有绑定表时改动旧数据区。

## 不动旧地址的硬约束

- 源 ROM 的原 PRG Bank `$00-$3F` 逐字节不变。
- 除 iNES 文件头偏移 `$04` 从 `$20` 改为 `$40` 外，源文件旧范围 `$000010-$0C000F` 整体逐字节不变。
- 原 CHR 在旧文件位置保留为 PRG Bank `$40-$5F` 的影子副本，并在 1 MiB PRG 后再附加一份活动 CHR。
- 角色/地图曲目表本轮没有修改。

因此，配套修改器的正确顺序是：

1. 先让旧修改器修改 512 KiB PRG 的 `新DC上/下.nes`。
2. 再用 `tools/build_refined15_roms.py --allow-modified-input` 对修改后的 ROM 扩容。
3. 不建议先扩容再用旧修改器；旧修改器不会同步 `$60/$7E/$7F` 的活动副本。

## PRG 布局

| Bank | 内容 |
| --- | --- |
| `$00-$3F` | 原 PRG，完全不改 |
| `$40-$5F` | 原 CHR 在旧文件偏移处形成的影子副本 |
| `$60` | 原音频 Bank `$18` 的扩容副本、入口跳板、FCEUX 安全交还代码 |
| `$61-$63` | 清空；旧测试版的 3 首 FamiStudio 曲目已删除 |
| `$64` | 双引擎桥接代码；不再保存旧 FamiStudio 引擎 |
| `$65-$73` | 15 首精修曲的数据 Bank |
| `$74` | 重定位后的通用驱动与包装器 |
| `$75` | 同一驱动及 `It's Not Anime` 的第三数据页 |
| `$76` | Bank 切换跳板 |
| `$77` | 迁移后的 56 个原版音效完整状态快照 |
| `$78-$7D` | 保留空白 |
| `$7E/$7F` | 扩容后的固定 Bank 副本 |

运行时只有两套音乐引擎：原版 DC 引擎与精修 15 曲共用驱动。原版音效不是第三套音乐引擎；新曲播放时由有界叠加器继续处理 `$00-$37` 的 56 个音效。Bank `$77` 中每条记录保存当前效果的完整寄存器状态，运行成本不再随效果已经播放的时长增长。

## 公共驱动的接入方式

15 个 NSF 的首个 4 KiB 驱动页逐字节相同。构建器不会把 NSF 的 `$5FF8-$5FFF` 换页机制直接塞进卡带，而是：

1. 从 NSF 提取公共驱动页和各曲数据页。
2. 从 `$F000` 反汇编可达的 6502 路径，将代码引用重定位到 `$B000`。
3. 把 150 字节持久状态按连续数组打包到原音频驱动已审计的 RAM 洞中，避开游戏接口 `$004C-$0056`；逻辑 `$0294/$0295` 固定映射到 `$0468/$0469`，逻辑 `$0296/$0297` 映射到 `$002A/$002B`，不再占用游戏每帧用作间接指针的 `$0028/$0029`。桥接状态仅保留 `$046A/$046B` 两字节。
4. 去除 15 首均未使用的第五/DMC 通道路经，将更新循环限制为四个 2A03 音调通道。
5. 用 Mapper 194 的 R6/R7 映射歌曲数据和驱动 Bank。
6. 将公共驱动中两条可达的 `STA $5FF8,X` 改为 `STA $48F8,X`；ROM 内 Bank 已由包装器显式设置，不能再让 NSF 虚拟换页寄存器碰到 Mapper 194 的真实寄存器。

这项实现与计划草案中的“从 FamiStudio 源码重新编译”不同：最终采用的是对实际 NSF 公共驱动的可达代码重定位，以锁定精修文件真实使用的功能组合。重定位规则、输出汇编和运行时 RAM 越界均有自动化门禁。

## FCEUX 兼容处理

FCEUX 2.6.6 的 MMC3 通用层会安装 KT-008 `$5000` 写处理。若其私有 PRG 高位锁存器被游戏流程意外置位，原版 Bank 访问在 1 MiB PRG ROM 中可能被抬高 `$40`。桥接器在交还控制权前执行 `A=$27 / STA $5000` 清除该锁存器；Mesen 与实际 Mapper 194 对该未映射写入不响应。

这不是“高 Bank 在 FCEUX 一律回绕到低 512 KiB”的兼容副本方案。两套模拟器均直接运行 `$60/$64/$65-$77/$7E-$7F` 的真实扩容 Bank。

## 琉妮攻击花屏修复

故障版在新曲播放期间用“每帧从头重放音效已消费前缀”的方法叠加原版音效。武器音效 `$18` 越往后，单帧重放的读取和 APU 写入越多；与战斗光束的扫描线 IRQ 同时发生时，会挤占 NMI/IRQ 时序并使 CHR 映射在错误时刻被改写。实测故障帧的桥接更新可达约 14000～25000 CPU 周期。修复后的完整状态快照每帧最多只重写当前效果实际使用的寄存器，13 个历史故障窗口的峰值不超过 3905 周期，关键帧全部一致。

同时修复两个独立隐患：驱动逻辑 `$0294/$0295` 不再落到游戏的 `$0028/$0029`，两条 NSF `$5FF8` 写入不再触碰 Mapper。详细证据见 `docs/琉妮攻击花屏根因与修复.md`。

## 构建

需要 Python 3、`capstone` 和 FamiStudio 附带的 `asm6_fixed.exe`：

```powershell
python tools\build_refined15_roms.py --asm6 D:\path\to\asm6_fixed.exe
```

对旧修改器处理后的 ROM 构建时：

```powershell
python tools\build_refined15_roms.py `
  --upper D:\path\to\modified-upper.nes `
  --lower D:\path\to\modified-lower.nes `
  --allow-modified-input `
  --no-dist `
  --asm6 D:\path\to\asm6_fixed.exe
```

先用 `--no-dist` 检查 `build/refined15/构建校验.json`，确认后再生成正式交付物。

对已经过旧修改器处理、不能从 512 KiB 基线重建的 v1 扩容 ROM，可只替换扩容区音频运行时代码：

```powershell
python tools\repair_refined15_expanded_roms.py `
  --upper-expanded D:\path\to\upper-expanded.nes `
  --lower-expanded D:\path\to\lower-expanded.nes `
  --asm6 D:\path\to\asm6_fixed.exe
```

修复工具不覆盖输入；它逐字节保留旧地址文件体、Bank `$65-$73` 的 15 曲数据和活动 CHR，仅重建 `$60` 的桥接槽及 `$64/$74-$77` 音频运行时 Bank。
