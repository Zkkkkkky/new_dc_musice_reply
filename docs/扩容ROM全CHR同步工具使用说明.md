# 扩容 ROM 全 CHR 同步工具

## 适用前提

用户已确认：当前使用的旧修改器只会写入扩容前的 CHR 文件区域，不会改写活动 CHR、扩容音乐 Bank 或固定 Bank 副本。

本工具因此把旧 CHR 影子视为权威数据，每次将完整 256 KiB 复制到模拟器使用的活动 CHR：

```text
旧 CHR 影子  0x080010–0x0C000F
       ↓ 整区复制
活动 CHR     0x100010–0x14000F
```

## 标准流程

1. 用原版旧偏移修改器打开 1 MiB PRG 扩容 ROM。
2. 修改标题、字库、头像、地图图块或其他 CHR 图形并保存。
3. 优先双击免 Python 交付物 `dist\tools\扩容ROM全CHR同步工具.exe`。源码版可双击 `tools\启动扩容ROM全CHR同步工具.cmd`。
4. 选择修改器刚保存的 ROM。
5. 核对工具报告的差异字节数和范围。
6. 点击“同步并另存”，生成 `*_CHR已同步.nes`。
7. 使用新 ROM 在 FCEUX 和 Mesen 中检查对应画面。

注意：模拟器必须打开第 6 步生成的 `*_CHR已同步.nes`，不是旧修改器刚保存的原文件。例如本次机体拼图验证中，应测试 `新DC (3)_CHR已同步.nes`，不应测试 `新DC (3).nes`。

机体变形形态是独立记录。例如 `$09` 「刚达」与 `$0A` 「刚达（MA）」的拼图脚本不是同一条；验证时需进入对应形态的战斗画面。

## 安全边界

- 只支持 Mapper 194、1 MiB PRG、256 KiB CHR、无 Trainer 的已验证布局。
- 不覆盖源 ROM，只能另存新文件。
- 不修改 Header、`$00-$7F` PRG Bank、音乐驱动、桥接器或事件数据。
- 实际写入限于活动 CHR `0x100010–0x14000F`，且只有与旧影子不同的字节会发生变化。
- 保存后会重新解析 ROM，并强制验证两份 CHR 差异为 0。

## 运行依赖

- `扩容ROM全CHR同步工具.exe` 由 C# WinForms 编译，不依赖 Python。
- 它仅需 Windows 自带的 .NET Framework 4.x；Windows 10/11 默认具备该运行环境。
- `.cmd/.pyw` 便携源码版仍保留，用于审计和二次开发。

## 不能与哪些流程混用

不要在“已打补丁、直接写入活动 CHR”的修改器之后运行本工具。那种情况下，旧影子反而是过时副本，执行旧→新同步会撤销新修改。

两条流程二选一：

```text
原版旧偏移修改器 → 本同步工具 → 模拟器

或

扩容 CHR 专用修改器 → 模拟器
```
