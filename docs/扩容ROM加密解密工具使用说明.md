# 扩容 ROM 加密解密工具

## 用途

该工具实现旧「加密.exe」的固定偏移变换，并为本项目 1 MiB PRG 扩容布局增加运行时 Bank `$7F` 同步。它不是密码学加密工具。

支持两种严格布局：

- 512 KiB PRG＋256 KiB CHR 原版，总大小 `$0C0010`；
- 1 MiB PRG＋256 KiB CHR 扩容版，总大小 `$140010`。

两者都必须是 iNES 1.0、Mapper 194、不带 Trainer，并且关键字节必须严格匹配已知加密态或解密态。

## 原理与为什么模拟器仍能运行

这种“加密”不是 AES 一类密码学加密，也没有加密整个 PRG/CHR。它只是在固定位置交换一个 `$9D80` 指针，再把固定 Bank 中的选择值由 `$11` 改为 `$17`。后者的具体业务含义是根据字节位置和运行现象得出的推断，不把它当作密钥。

模拟器只根据 iNES Header 建立 Mapper 和 PRG/CHR 映射，然后从复位向量开始执行。该变换没有改 Header、复位向量、绝大部分 CPU 代码或 CHR，ROM 也没有必须通过的签名/全文校验，所以它仍是合法可运行的 NES ROM。变化只会在游戏自己读取这几个配置字段时生效。

原工具只写低 512 KiB 固定 Bank 副本。本项目的 1 MiB 扩容 ROM 运行时使用 Bank `$7F`，因此本工具必须把 `$07F4C8` 和 `$0FF4C8` 一起修改，否则磁盘上看似“加密”，实际运行的高 Bank 却仍是解密态。

## 启动

直接双击免 Python 单文件版：

```text
dist\tools\扩容ROM加密解密工具.exe
```

使用源码版：

```text
tools\启动扩容ROM加密解密工具.cmd
```

## 修改规则

解密态：

```text
0x004012–0x004013 = 80 9D
0x00401E–0x00401F = 00 00
0x07F4C8             = 11
0x0FF4C8             = 11  （仅扩容版）
```

加密态：

```text
0x004012–0x004013 = 00 00
0x00401E–0x00401F = 80 9D
0x07F4C8             = 17
0x0FF4C8             = 17  （仅扩容版）
```

原版转换必须恰好改变 5 字节；扩容版必须恰好改变 6 字节。其他 Header、PRG、扩容音乐 Bank、CHR 和文件大小必须保持不变。

## 安全规则

1. 只能「另存」，不允许覆盖源 ROM。
2. 对尺寸、Mapper、Trainer、NES 2.0 和关键字节状态进行严格校验。
3. 拒绝重复加密、重复解密或 Bank `$3F/$7F` 状态不一致的 ROM。
4. 输出使用同目录临时文件原子替换，完成后重新读取并比对全文件、状态和 SHA-256。
5. 该工具仅适用于本项目已验证的 DC 家族 Mapper 194 布局，不得对其他 ROM 强行套用固定偏移。
