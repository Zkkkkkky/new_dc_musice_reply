# 扩容 ROM 全 CHR 同步验证

## 静态边界

- 同步源：`0x080010-0x0C000F`，共 `0x40000` 字节。
- 同步目标：`0x100010-0x14000F`，共 `0x40000` 字节。
- 方向：旧 CHR 影子→活动 CHR。
- 输入限制：Mapper 194、1 MiB PRG、256 KiB CHR、无 Trainer、文件大小 `0x140010`。
- 输出限制：禁止覆盖源 ROM；所有变化只能位于活动 CHR。

## 用户 ROM 演练

输入：`D:\QQDwwnloads\2 (1).nes`

- 大小：1,310,736 字节。
- 输入 SHA-256：`2781F88035B26FC0900175ACDA3033058079C894C30A990B0E0F37F002CE94A4`。
- 工具检出旧/活动 CHR 相差 2,621 字节。
- 输出仅修改活动 CHR 的 2,621 字节，首末偏移为 `0x114031-0x114DE0`。
- 活动 CHR 以外变化：0 字节。
- 同步后旧/活动 CHR 差异：0 字节。
- 源 ROM 哈希在演练后保持不变。
- 演练输出 SHA-256：`47251A6A6E851DDB5A28AE80BF0110D4424BE889B6065225BE644CD72E5935CD`。
- 演练输出仅位于忽略的 `build/chr-sync-smoke/`，未纳入 ROM 交付物。

## 自动化验证

`python -m unittest discover -s tests -v`：16 项全部通过，其中 3 项专门锁定全 CHR 同步边界、原版 ROM 拒绝与源文件保护。

## 免 Python EXE

- 实现：.NET Framework 4.x C# WinForms，单文件 12,800 字节。
- SHA-256：`7BAE2B95E18F7D6165F49F072F937103CB825828C5C5DEDDF307D019B4D39851`。
- 运行时不依赖 Python，仅使用 Windows 10/11 自带的 .NET Framework 4.x。
- 最终 EXE 通过内置 `--self-test` 处理用户 `2 (1).nes`：识别并同步 2,621 字节，活动 CHR 外改动为 0，输出 SHA-256 为 `47251A6A6E851DDB5A28AE80BF0110D4424BE889B6065225BE644CD72E5935CD`。
- Windows Defender 自定义扫描完成，该 EXE 路径匹配威胁记录为 0。
- 系统自带的旧 C# 编译器会为每次构建生成不同模块标识，因此 EXE 不承诺逐字节可重复构建；交付清单锁定上述最终哈希。
